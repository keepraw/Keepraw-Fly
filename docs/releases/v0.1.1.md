# Keepraw-Fly v0.1.1

Security & Reliability Maintenance Release · 安全与可靠性维护版本

Maintainer / 维护者：**keepraw**

## English

This maintenance release includes the security and engineering hardening in
[PR #77](https://github.com/keepraw/Keepraw-Fly/pull/77) and the subsequent
Node.js 24-compatible `actions/upload-artifact` update. It retains the existing
local-first application and browser storage model.

### Security and reliability

- Production builds enforce a strict Content Security Policy without
  `unsafe-inline` or `unsafe-eval`; Ajv validation uses precompiled code. Static
  Pages deployments use a CSP meta tag. Docker/Caddy adds response headers,
  clickjacking protection and HSTS on HTTPS only. Meta CSP cannot enforce
  `frame-ancestors` on GitHub Pages.
- The six MiSans CSS files use SHA-384 Subresource Integrity. Modified stylesheets
  are refused and system fonts remain available. This does not independently
  integrity-check the WOFF2 files referenced by those stylesheets.
- Export without personal details removes names, PNRs, ticket numbers and frequent
  flyer numbers. Retained extensions use an explicit field whitelist; unknown
  fields, nested objects and arrays are dropped. Full backups retain the original
  data, and sharing does not change IndexedDB. Routes and exact dates remain, so
  these exports are **not anonymous**.
- JSON, CSV and Flighty CSV imports enforce a 64 MB file limit and 100,000-record
  limit. CSV handles quoted fields, delimiters and embedded newlines. Storage
  migration retries are bounded; historical archives remain supported.
- GitHub Actions use full commit SHA pins, including Node.js 24-compatible
  `actions/upload-artifact` v7.0.2. Releases reuse the exact successful main CI
  build instead of rebuilding the application.

### Distribution and source verification

The release pipeline checks that the main CI commit, release workflow event
commit and version tag resolve to one source commit. It generates separate
Sigstore-backed GitHub Artifact Attestations for the release files and OCI image
digest, including the `SHA256SUMS` manifest itself. The installer requires GitHub CLI **2.102.0 or newer** and verifies the
official repository, `release.yml@refs/heads/main`, source commit, GitHub-hosted
runner and image digest before pulling the image. Missing or invalid proofs stop
installation. Mock-based regression tests alone are not evidence of a valid
release signature; publishing requires the real verification gates to pass.

Static ZIP/tar.gz, Docker images for linux/amd64 and linux/arm64, installer,
Compose, Caddy configuration and bilingual deployment guides use the verified CI
build. The immutable image digest and exact source/run references are recorded in
the published provenance. Only **keepraw** may create and publish the GitHub
Release; CI may build, attest and attach verified artifacts to an owner draft.

### Upgrade and compatibility

Application packages advance from **0.1.0 to 0.1.1**; the canonical archive
`formatVersion` remains **0.1.0**. Website updates do not intentionally clear
existing IndexedDB records. Export a full JSON backup before upgrading and retain
the same origin to continue using browser data.

v0.1.0 releases, tags and images remain unchanged and checksum-only. The v0.1.1
installer retains explicit v0.1.0 rollback support without describing that older
release as attested. See the [deployment guide](../deployment.md).

This release does not add guaranteed offline PWA startup, encrypted cloud sync,
the planned Passport map/Flight Detail redesign or a flight passport poster
generator. The recorded `braces` advisory affects the development CSS lint chain;
see the [dependency review](../reviews/2026-10-16-dependency-security.md).

## 简体中文

本维护版本包含 [PR #77](https://github.com/keepraw/Keepraw-Fly/pull/77) 的安全与工程
加固，以及后续 `actions/upload-artifact` 的 Node.js 24 兼容升级，继续保持 local-first
和浏览器本地存储设计。

### 安全与可靠性

- 生产构建采用不含 `unsafe-inline`、`unsafe-eval` 的严格 CSP，Ajv 使用预编译校验代码。
  Pages 使用 CSP Meta；Docker/Caddy 额外设置安全响应头、防嵌入策略及仅 HTTPS 下的
  HSTS。GitHub Pages 的 CSP Meta 无法强制执行 `frame-ancestors`。
- 六个 MiSans CSS 文件通过 SHA-384 SRI 校验，样式被篡改时拒绝应用并降级至系统字体。
  CSS 所引用的 WOFF2 文件不具备独立的浏览器 SRI 验签。
- 脱敏导出移除姓名、PNR、票号和常旅客号码，保留扩展仅允许明确字段，丢弃未知字段、
  嵌套对象和数组。完整备份保留原始信息，分享操作不修改 IndexedDB。具体航线和日期
  仍然保留，因此分享文件**并非完全匿名**。
- JSON、CSV、Flighty CSV 导入限制为 64 MB、100,000 条记录，兼容 CSV 引号、分隔符和
  字段内换行。存储迁移并发重试具有上限，历史档案继续兼容。
- GitHub Actions 使用完整 Commit SHA 固定，`actions/upload-artifact` v7.0.2 原生支持
  Node.js 24。发行流程复用成功 main CI 的原始应用产物，不重新构建应用。

### 发行与来源验证

发行流程要求 main CI、Release Workflow 事件和 Tag 指向同一源码提交，分别为发行附件和
OCI 镜像 digest 生成基于 Sigstore 的 GitHub Artifact Attestations，附件证明也覆盖
`SHA256SUMS` 清单本身。安装器要求
GitHub CLI **2.102.0 或更新版本**，拉取镜像前核验官方仓库、
`release.yml@refs/heads/main`、源码提交、GitHub 托管 runner 和镜像 digest；缺失或无效
的证明会阻止安装。模拟回归测试不能代替真实签名验证，正式发布必须通过实际验签门禁。

静态 ZIP/tar.gz、linux/amd64 与 linux/arm64 Docker 镜像、安装器、Compose、Caddy 配置
和中英文部署指南使用经过验证的 CI 构建，实际镜像 digest、源码与工作流运行记录写入
发行来源信息。GitHub Release 必须由 **keepraw** 本人创建和发布；CI 可以构建、签发证明，
并向 Owner Draft 上传经过验证的附件。

### 升级与兼容性

应用 package 版本从 **0.1.0 升至 0.1.1**，档案 `formatVersion` 保持 **0.1.0**。
网站更新不会主动清空现有 IndexedDB。升级前导出完整 JSON 备份，保持同一来源地址才能
继续使用原浏览器数据。

历史 v0.1.0 Release、Tag、镜像保持不变，仍属于 checksum-only。v0.1.1 安装器保留显式
回滚到 v0.1.0 的能力，不将历史版本描述为已经签名。操作参见[中文部署指南](../deployment.zh-CN.md)。

本次不包含完整离线 PWA、端到端加密云同步、计划中的 Passport 地图或 Flight Detail
改版，也不包含飞行护照海报生成器。既有 `braces` 告警涉及开发期 CSS lint 依赖链，
评估见[依赖安全审查](../reviews/2026-10-16-dependency-security.md)。
