# Keepraw-Fly v0.1.0

The first public release of Keepraw-Fly, published by **keepraw**. Use it at <https://fly.keepraw.com> or host the prebuilt website on GitHub Pages or a Linux VPS. End users do not need Node.js, pnpm or a source build.

## Included capabilities

- Flight Passport with lifetime/yearly statistics, airports, airlines, aircraft, routes and delays.
- Searchable flight archive with add, edit, duplicate and detail views; desktop route maps.
- Validated JSON backup/migration, mapped Keepraw Fly CSV bulk import and supported Flighty CSV import with duplicate review.
- Frequent-flyer profiles and responsive layouts in ten locales.
- Local-first IndexedDB storage with optional browser persistent-storage requests.

This release adds deployment and distribution tooling without changing flight business logic, UI or the IndexedDB data contract. Application version **0.1.0** and archive Schema version remain independently managed.

## Installation and verification

- **Online:** <https://fly.keepraw.com> — no installation.
- **Fork Pages:** Fork → enable Actions → Settings/Pages: GitHub Actions → run **Deploy official release to Fork Pages**, version `v0.1.0`. No install/build/E2E jobs. Fork source changes are not included in this prebuilt mode.
- **VPS:** install Docker Engine + Compose v2, download/check/inspect `install.sh` and run with a domain for automatic Caddy HTTPS. Follow the attached bilingual deployment guides.
- **Other static hosts:** extract `keepraw-fly-v0.1.0.zip` or `keepraw-fly-v0.1.0.tar.gz` and serve the directory containing `index.html` over HTTPS.

`SHA256SUMS` covers all release attachments except itself. The static archives include `release.json` (version, commit, author) and `FILES.sha256`. The official `ghcr.io/keepraw/keepraw-fly:v0.1.0` image supports **linux/amd64** and **linux/arm64**, runs only Caddy/static files and has no Node.js/pnpm production runtime. `image.txt` contains its immutable digest reference; the installer uses it. `provenance.json` links the exact successful main CI build and image workflow. ZIP, tar.gz, official Pages and Docker use that same production build. No moving `latest` tag is required.

Official CI retains documentation/formatting/CSS/type/unit/build checks, the full six-shard Chromium regression and Firefox/WebKit compatibility smoke tests. All must succeed before official Pages deployment or release artifact promotion. Release publication uses the `keepraw` account after draft attachment verification; Actions does not create a bot-authored Release.

## Data, upgrades and limitations

Flight archives are stored **only in the current browser's IndexedDB**, not on GitHub Pages or the VPS. There are no accounts, server database or automatic cross-device cloud sync. Data is separate across origins, browser profiles and devices. Export JSON regularly and before migration/upgrades. Deploying a new version does not intentionally clear archives; Docker upgrades do not back up or move personal data. Keep the origin stable, and review Schema compatibility before rolling back future versions.

Upgrades and rollbacks select an explicit release version. The installer can be rerun, checks existing ownership/configuration and ports, preserves prior configuration and restores it on startup failure. Public HTTPS requires working domain DNS and inbound TCP 80/443; container health alone does not verify public certificate issuance. Browser storage policies and eviction still apply. Reference datasets are bundled and are not live flight-status data. Chinese fonts retain the existing external fixed-version CDN dependency and system-font fallback. Existing license, trademark and third-party declarations remain in effect.

See the attached English and Chinese deployment guides for maintenance, backup, uninstall and troubleshooting. Full real-world VPS validation depends on an actual public server/domain; container integration results are recorded in the release PR.
