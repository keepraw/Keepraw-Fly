# Keepraw-Fly v0.3.0 — 2D Maps and Airport History

Stable feature release · 正式功能版本

Maintainer / 维护者：**keepraw**

## English

v0.3.0 replaces the 3D globe with shared 2D maps, resolves airports by date
against a bundled airport history, and adds Umetrip XLS import. It includes the
changes since v0.2.0 and retains the browser-local flight archive model.

### New: 2D maps and map themes

- Passport and Flight Detail draw their routes on a shared 2D SVG map. The 3D
  globe, Three.js and the WebGL share renderer are removed; the application no
  longer needs WebGL.
- Settings offers a **map theme**: Neon Aviation or Daylight Chart. It applies to
  the Passport map and the flight route map.
- Settings offers a **Flight Passport layout** for the shared image: the new Neon
  sheet, which follows the map theme, or the classic passport book from v0.2.0.

### New: date-aware airport history

- Airports are resolved against the bundled Keepraw Airport History 0.14.0
  (Schema 4.0.0), so a code that moved between physical sites resolves to the
  site in use on the flight date. Airport names are localized.
- A flight can store an optional permanent airport ID on its origin,
  destination and diversion, next to the recorded IATA code. Routes,
  statistics, time zones, distances and share images use that identity.
- The earlier online airport research lookup is removed. Airports are resolved
  only from data shipped with the site.

### New: Umetrip XLS import

- Preview and append used historical flights from the supported Umetrip Excel
  export. Unused, OPEN, refunded, exchanged and invalid tickets are excluded.
  Compatibility has been checked against one real export only; see the
  [supported layout and limitations](../schema.md#umetrip-xls-import).

### Improvements and fixes

- The startup screen appears before the application and the airport reference
  data load. The entry script drops from about 490 kB to about 134 kB gzip, and
  the two large airport data chunks are no longer preloaded.
- Passport route lines stay solid when the map is zoomed. The import and share
  actions are outlined buttons, the arrival-delay total no longer uses the
  danger color, and flight numbers use the primary text color.
- Settings marks a missing backup as a warning, no longer shows a disabled
  button once persistent storage is granted, and drops duplicated CSV and
  Flighty import descriptions.
- Audit remediation for import, recovery and history correctness: recovery
  copies preserve repeated JSON values, and large archives import and recover
  more reliably.
- Fixed Passport accessibility crashes on Firefox 159 mobile and stabilized
  locale reloads on WebKit.
- Updated Soaring Symbols airline icons to alpha.14 and workspace dependencies.
  Full and production dependency audits report no known vulnerabilities; see the
  [current security review](../security.md#known-dependency-advisory).

### Engineering maintenance

- Removed the unused `solarMode` setting, dead barrel modules and Globe-era
  documentation. A stored `solarMode` value is ignored.
- The E2E WebGL guard refuses every WebGL context type, and export specs that
  render twice have a matching time budget.

### Data compatibility, upgrade and rollback

Application packages advance from **0.2.0 to 0.3.0**. Archive **`formatVersion`
advances from `0.1.0` to `0.2.0`** to carry the optional airport IDs. v0.3.0
imports both `0.1.0` and `0.2.0` archives and exports `0.2.0`. The IndexedDB
database version is unchanged.

**v0.2.0 and earlier cannot import a `0.2.0` archive**: their schema accepts only
`0.1.0`. **Export a full Keepraw Fly JSON backup with your current version
before upgrading** and keep it; it is the only backup an older version can
import. Rolling back after saving data with v0.3.0 is not a tested path.

Flight records still live in the current browser origin's IndexedDB. Updating
website files does not intentionally clear them. Retain the same scheme,
hostname, port and browser profile; export/import JSON when moving origins or
devices. Docker hosts website files, **not personal flight backups**. There is no
account, cloud synchronization or server restore copy.

Docker users download and verify this release's installer, then select
`--version v0.3.0 --dir /opt/keepraw-fly`. Omit address flags to retain existing
hostname and ports. Fork Pages users select v0.3.0 in the existing
official-release workflow. Static-host users deploy the verified ZIP/tar.gz over
HTTPS. See the [deployment guide](../deployment.md) for prerequisites and
commands.

Historical Releases, tags and images remain unchanged. The v0.3.0 installer can
explicitly select v0.2.0, v0.1.1 or v0.1.0; see the archive-format limit above
before rolling back.

### Distribution and known limits

Static archives and linux/amd64 + linux/arm64 Docker images reuse the **exact
successful main Push CI build**. The existing workflow requires CI, tag and
workflow source commits to match; it generates SHA256SUMS, provenance and
separate Sigstore-backed file/image attestations. The Owner-only publisher
verifies them and anonymous image access before publishing as **keepraw**. The
installer requires GitHub CLI **2.102.0 or newer**; missing or invalid proofs
stop installation.

- Chromium runs the full regression suite in CI; Firefox and WebKit run the
  compatibility subset. No physical-device test is part of this release.
- Umetrip XLS import has been checked against one real export.
- See [current product boundaries](../not-implemented.md) for capabilities that
  are not implemented.

## 简体中文

v0.3.0 用共享的 2D 地图取代 3D 地球，按航班日期对照内置的机场历史数据解析机场，并新增航旅纵横
XLS 导入。本版本包含 v0.2.0 之后的全部改动，航班档案仍只保存在浏览器本地。

### 新增：2D 地图与地图主题

- Passport 和航班详情在共享的 2D SVG 地图上绘制航线。3D 地球、Three.js 和 WebGL
  分享渲染器已删除，应用不再需要 WebGL。
- 设置中可选择**地图主题**：Neon Aviation 或 Daylight Chart，作用于 Passport 地图和航班航线
  地图。
- 设置中可选择分享图片的 **Flight Passport 版式**：新的 Neon 版式（跟随地图主题），或 v0.2.0
  的经典护照册。

### 新增：按日期解析的机场历史

- 机场对照内置的 Keepraw Airport History 0.14.0（Schema 4.0.0）解析：同一代码先后对应不同
  物理机场时，按航班日期解析到当时在用的机场。机场名称已本地化。
- 航班的出发、到达和备降机场可以在记录的 IATA 代码之外，各自保存一个可选的永久机场
  ID。航线、统计、时区、距离和分享图片都使用这个身份。
- 早期的在线机场查询已删除，机场只用随网站发布的数据解析。

### 新增：航旅纵横 XLS 导入

- 可预览并追加受支持的航旅纵横 Excel 导出文件中已使用的历史航班。未使用、OPEN、退票、改签和
  无效客票会被排除。兼容性只用一份真实导出文件验证过，见
  [支持的格式与限制](../schema.md#umetrip-xls-import)。

### 改进与修复

- 启动页先显示，再加载应用和机场参考数据。入口脚本从约 490 kB 降到约 134 kB（gzip），两个
  大的机场数据块不再预加载。
- Passport 地图放大后航线保持实线。“导入航班”和“分享飞行护照”改为带边框的按钮，到达晚点
  合计不再使用危险色，航班号改用主文字颜色。
- 设置页把“尚未备份”显示为警示，持久存储已启用后不再显示禁用按钮，并删除了 CSV 和 Flighty
  导入的重复说明。
- 导入、恢复和历史数据正确性的审计修复：恢复副本保留重复的 JSON 值，大档案的导入和恢复更
  可靠。
- 修复 Firefox 159 移动端 Passport 的无障碍崩溃，并稳定 WebKit 下切换语言后的重新加载。
- Soaring Symbols 航司图标更新到 alpha.14，并更新了工作区依赖。完整依赖和生产依赖审计均未
  报告已知漏洞，见[当前安全审查](../security.md#known-dependency-advisory)。

### 工程维护

- 删除未使用的 `solarMode` 设置、无引用的 barrel 模块和 Globe 时代的文档。已保存的
  `solarMode` 值会被忽略。
- E2E 的 WebGL 守卫拒绝所有类型的 WebGL 上下文；需要渲染两次的导出用例有了相应的时间预算。

### 数据兼容性、升级与回滚

应用 package 版本从 **0.2.0 升到 0.3.0**。为保存可选的机场 ID，档案 **`formatVersion` 从
`0.1.0` 升到 `0.2.0`**。v0.3.0 可导入 `0.1.0` 和 `0.2.0` 档案，导出为 `0.2.0`。IndexedDB
数据库版本不变。

**v0.2.0 及更早版本无法导入 `0.2.0` 档案**：它们的 Schema 只接受 `0.1.0`。**升级前请先用当前
版本导出完整的 Keepraw Fly JSON 备份**并妥善保存，这是旧版本唯一能导入的备份。用 v0.3.0 保存
过数据之后再回滚，没有经过测试。

航班记录仍保存在当前浏览器来源的 IndexedDB 中。更新网站文件不会主动清空它们。请保持协议、
域名、端口和浏览器配置不变；更换来源地址或设备时用 JSON 导出和导入。Docker 托管的是网站
文件，**不是个人航班备份**。没有账号、云同步或服务器端恢复副本。

Docker 用户下载并校验本版本的安装器，然后使用 `--version v0.3.0 --dir /opt/keepraw-fly`。
不传地址参数会保留现有域名和端口。Fork Pages 用户在现有的官方发行流程中选择 v0.3.0。静态
托管用户通过 HTTPS 部署已校验的 ZIP/tar.gz。前提条件和命令见[部署指南](../deployment.zh-CN.md)。

历史 Release、Tag 和镜像保持不变。v0.3.0 安装器可以显式选择 v0.2.0、v0.1.1 或 v0.1.0；回滚
前请先阅读上面的档案格式限制。

### 发行与已知限制

静态压缩包和 linux/amd64 + linux/arm64 Docker 镜像复用**同一次成功的 main Push CI 构建**。
现有流程要求 CI、Tag 和工作流的源提交一致，并生成 SHA256SUMS、provenance 以及分别由 Sigstore
签发的文件和镜像来源证明。仅限 Owner 的发布脚本会先校验这些证明和匿名镜像访问，再以
**keepraw** 身份发布。安装器需要 GitHub CLI **2.102.0 或更新版本**；证明缺失或无效时停止安装。

- CI 中 Chromium 运行完整回归，Firefox 和 WebKit 运行兼容性子集。本版本没有真机测试。
- 航旅纵横 XLS 导入只用一份真实导出文件验证过。
- 尚未实现的能力见[当前功能边界](../not-implemented.md)。
